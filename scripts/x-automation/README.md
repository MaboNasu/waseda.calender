# Waseda Calendar X自動投稿

Waseda Calendar公式X(@waseda_calendar)への投稿を、人の手を介さず自動で判断・実行する仕組み。

> セットアップが済んでいれば、日常的にXを開いて操作する必要はありません。このファイルは「動かし方」、初回セットアップの手順は [docs/x-automation-setup.md](../../docs/x-automation-setup.md) を参照してください。

---

## 概要

| 項目 | 内容 |
|---|---|
| 投稿先 | X(旧Twitter) @waseda_calendar |
| 実行タイミング | 毎朝7:30 JST・毎昼12:30 JST(GitHub Actions) |
| 文章生成 | テンプレート方式(Claude APIは使わない、無料) |
| 投稿判断 | 決定論的なロジック(条件を満たすときだけ投稿) |
| コスト | X API従量課金のみ、月あたり数ドル程度(URL付き投稿1件$0.20) |
| 人がやること | 通常はなし。週1回程度の振り返りは推奨 |

---

## 投稿タイプ

朝枠(7:30)では、以下4種類を毎回すべて候補として評価したうえで、**優先順位(今週の早稲田→今日の早稲田→テーマ型→おすすめ誘導)に従って最も価値が高い1件だけ**を投稿します。「今日このあと」だけは昼枠(12:30)で独立して判定されます(朝に何が投稿されたかに関係なく評価されます)。

| 投稿タイプ | 頻度の目安 | 投稿条件 |
|---|---|---|
| 今週の早稲田 | 週1(月曜のみ) | 月曜日で、今週開催のイベントが1件以上ある |
| 今日の早稲田 | 条件次第 | 当日開催のイベントが3件以上ある |
| 今日このあと | 条件次第(昼枠・独立) | 開始時刻が確定していて90〜480分後に始まる、会場情報つきのイベントがある |
| テーマ型投稿 | 週0〜2 | 「一般参加可」「文化・講演」「週末」を日替わりでローテーションし、該当が3件以上ある |
| おすすめ機能誘導 | 週0〜1 | 今週のイベントのカテゴリが3種類以上ある(ジャンルが偏っている週は投稿しない) |

条件を満たしても、以下のいずれかに該当する場合はその投稿タイプ(朝枠は他の候補も含めて丸ごと)を見送ります。

- 直近7日間の合計投稿数が10件に達している(週全体の上限。`WEEKLY_TOTAL_POST_CAP`)
- そのタイプを本日分すでに投稿済み(二重投稿防止)
- 前回投稿から最低間隔日数が経っていない
- 直近の同タイプ投稿とイベントが半数以上重複している(内容の使い回し防止)

朝枠で選ばれなかった候補も「条件は満たしたが見送った」としてActionsのログに理由付きで残ります。投稿を1件に絞っているのは、同じ朝に複数投稿してbotっぽく見えるのを避けるためです(2026-08-18のChatGPTとの検討会議での指摘を反映)。

## 日常の運用

セットアップ後は基本的に**何もしなくてよい**設計です。GitHub Actionsが毎朝・毎昼に自動実行し、実行結果は次の形で確認できます。

- **実行ログ**: リポジトリの Actions タブ → 該当ワークフロー(「X投稿(朝・...)」「X投稿(昼・...)」)を開くと、その回の判断結果(投稿した/見送った理由)が全て見える
- **投稿履歴**: [post-log.json](post-log.json) に、投稿した(またはDry Runで投稿するはずだった)内容の要約が自動で記録・コミットされる

たまにXの投稿画面を見て、内容や頻度に違和感がないか確認する程度で十分です。

## 止め方・再開のさせ方

すべてGitHubの画面上の設定変更だけで完結し、コードの変更やデプロイは不要です。

| したいこと | 操作 |
|---|---|
| 一時停止する | Settings → Secrets and variables → Actions → Variables で `X_AUTOMATION_ENABLED` を `false` にする |
| 再開する | 同じ場所で `X_AUTOMATION_ENABLED` を `true` に戻す |
| 投稿はさせず判断だけ見たい | `X_DRY_RUN` を `true` にする(実際には投稿されない) |
| 完全に止める | `.github/workflows/x-post-morning.yml` と `x-post-midday.yml` を無効化(Actions画面から) |

詳しい初回設定手順(X Developer Portal・認証情報の発行)は [docs/x-automation-setup.md](../../docs/x-automation-setup.md) を参照してください。

## 週次振り返り

Claude Codeで `.claude/skills/x-weekly-review` スキルを使うと、直近の投稿傾向とGA4のデータをもとに振り返りができます。「Xの振り返りをして」のように話しかければ実行されます。

- どの投稿タイプがよく機能したか
- サイト流入が弱かった投稿はどれか
- 同じような内容を繰り返していないか
- 投稿頻度は多すぎ/少なすぎないか

を見た上で、`config.js` の閾値のような軽微な調整はその場で行い、投稿タイプの追加・停止のような大きな変更は提案のみに留めて相談する運用です。この分析にも外部の有料LLM APIは使いません(このセッションのモデル自身が判断するため追加コストなし)。

## ファイル構成

```
scripts/x-automation/
├── decide-and-post.js   # ★ メインの実行スクリプト(投稿判断〜投稿まで)
├── weekly-review.js     # 週次振り返り用の機械集計(判断はしない)
├── post-log.json        # 投稿履歴(GitHub Actionsが自動更新・コミット)
└── lib/
    ├── config.js         # 設定値(頻度・閾値など。調整はまずここ)
    ├── events-data.js    # events.js の読み込み、日付処理
    ├── eligibility.js    # 各投稿タイプの「投稿する価値があるか」判定
    ├── diversify.js      # カテゴリの偏りを防ぐ選定ロジック
    ├── copy-templates.js # 投稿文の生成(テンプレート方式)
    ├── url-builder.js    # UTMパラメータ付きURLの生成
    ├── post-log.js       # 投稿履歴の読み書き・重複防止チェック
    └── x-client.js       # X API呼び出し(OAuth 1.0a)
```

設定を変えたい場合は、まず `lib/config.js` を見てください。頻度・最低件数・上限などはすべてここにまとまっています。

## コストについて

X APIは従量課金で、無料枠・サブスクリプションはありません(2026-08時点)。本システムの投稿はすべてURLを含むため、投稿1件あたり約$0.20かかります。投稿頻度は既定で週数件程度に抑えてあるため、月額では数ドル程度の想定です。Developer Consoleで支出上限(Spending limits)を設定しておくことを強く推奨します(詳細は[セットアップ手順](../../docs/x-automation-setup.md)参照)。

Claude APIの呼び出しは投稿判断・文章生成のどこにも入っていないため、そちらのコストは常に0円です。

## トラブルシューティング

| 症状 | 確認すること |
|---|---|
| 何日も投稿されない | Actionsのログで「見送り」理由を確認(条件を満たすイベントがない可能性が高く、異常ではないことが多い) |
| 投稿してほしくない内容が出た | いったん `X_AUTOMATION_ENABLED=false` で停止し、`lib/config.js` や `lib/copy-templates.js` を確認 |
| エラーで失敗している | Actionsのログにエラー内容が出力される。認証情報(Secrets)の設定漏れ・期限切れが多い原因 |
| 二重投稿された | 通常は起きない設計(post-log.jsonで防止)。起きた場合はpost-log.jsonの内容を確認して報告してください |

## ローカルで試す場合

```bash
# 特定の日付を「今日」として動作確認したい場合(投稿はしない)
WC_NOW_OVERRIDE=2026-08-24 X_DRY_RUN=true node scripts/x-automation/decide-and-post.js --slot=all

# 週次振り返りの機械集計だけ試す
node scripts/x-automation/weekly-review.js 7
```
