# 標準作業フロー

ClaudeがUI/UXについて相談されたときに使う標準フロー。全フェーズを毎回フルに実行する必要はない——小さな相談ならPhase 1〜3で十分なこともある。判断に迷うとき・大きな変更のときほど、後半のフェーズを丁寧に行う。

## Phase 1: Goal（目的）

まず「この画面でユーザーは何を達成したいのか」を特定する。`waseda-calendar-ux.md`の最重要ユーザージャーニーのどの段階に当たるかを確認する。

例: 「イベント詳細ページ」→ Phase「参加可否を判断する」段階。「団体一覧」→ Phase「イベントを発見する」段階（団体経由）。

## Phase 2: Current State（現状把握）

**実際のコードを確認する。必要に応じて実データを確認する。推測だけで現状を評価しない。**

- 対象画面のHTML/CSS/JSを実際に読む（`design-system.md`に既にまとめた情報も使えるが、対象箇所は個別に確認する）。
- 対象がイベント一覧・詳細に関わるなら、`events.js`の実データを確認する（`waseda-calendar-ux.md`の実データ統計、または必要なら簡単なNodeスクリプトで確認——STEP 13相当、`review-checklist.md`のEdge Cases参照）。
- 静的生成パス（`scripts/generate-*.js`）とクライアント側パス（`script.js`等）の両方が同じ画面を描画している場合、両方を確認する（`CLAUDE.md`の「Every page is duplicated in two rendering paths」）。

## Phase 3: Problem（問題の定義）

問題を「UI上の現象」ではなく「ユーザー行動への影響」として定義する。

- 悪い例: 「ボタンが小さい」
- 良い例: 「主要CTAの視認性と操作性が低く、公式ページへ進む行動が認識されにくい」

この言い換えができない場合、それはまだ「問題」として成立していない可能性がある——見た目の好みに過ぎないかもしれない（`principles.md`のAesthetic-Usability Effect参照）。

## Phase 4: Research（調査）

必要に応じて以下を調査する（`research-sources.md`の「積極的に調査する」条件に当てはまる場合）。

- UX原則（`principles.md`）
- アクセシビリティ（`accessibility.md`）
- 既存パターン（`design-system.md`、実コード）
- 比較対象サービス（`research-sources.md`のTier 3、必要な場合のみ）

## Phase 5: Options（選択肢の検討）

重要な問題では、原則として複数案を検討する。

例:
- A案（最小限の修正）
- B案（中間的な変更）
- C案（大きな構造変更）

各案について以下を見る。

- UX効果
- 実装コスト
- メリット
- デメリット
- 副作用

小さな相談（明らかなバグ修正等）では複数案は不要——`decision-framework.md`と組み合わせて、規模に応じて省略してよい。

## Phase 6: Recommendation（推奨）

最も妥当な案を選ぶ。**Ownerの案が最善でないと判断した場合は反論する**（SKILL.mdの姿勢、`decision-framework.md`参照）。

## Phase 7: Implementation（実装）

**必要な場合のみ実装する。UI改善相談＝必ず実装、ではない。**

「レビューして」「どう思う？」という相談には、Phase 6までの報告で止める。実装まで求められた場合のみ着手し、`CLAUDE.md`のコード変更ルール（明示的に依頼された場合を除きcommit/push/mainマージをしない）に従う。

## Phase 8: Validation（検証）

実装した場合は必ず確認する。ただし検証の重さは変更のリスクに比例させる（`CLAUDE.md`「作業の進め方」参照）。

- 低リスク（色・アイコン等の見た目のみ）: コードレビュー＋簡単な目視確認で十分。
- 高リスク（機能追加、複数ページにまたがる共有ロジック、データに影響するUI）: Playwright等での自動確認、モバイル幅・PC幅の両方、実データでのエッジケース確認（`review-checklist.md`）まで行う。

過剰な検証（低リスクな変更にhover状態やアニメーションの多段階スクリーンショットを撮る等）は、それ自体が「手段の目的化」であり避ける。
