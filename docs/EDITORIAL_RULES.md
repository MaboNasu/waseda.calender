# 掲載基準・表記基準・出典ルール（EDITORIAL_RULES）

Waseda Calendar のイベント情報を「集める・確かめる・公開する・SNSに出す」すべての担当（クラウドの Claude Code、
運営者の Chrome で動く Claude、ChatGPT、運営者本人）が読む共通のルールです。2026-11-14 に運営者・Claude・ChatGPT で合意しました。

- 何が「イベント」か（EVENT / NOT_EVENT / REVIEW）は `EVENT_REVIEW_RULES.md`
- 転載・著作権・個人情報は `LEGAL_GUARDRAILS.md`
- 毎日の作業手順は `docs/DAILY_CYCLE.md`

**基本方針：収集は積極的に、公開は出典で確かめたものだけ、公開後も確かめ続ける。**
**AIの仕事は増やしてよいが、運営者の定常作業は増やさない（確認は1日10件・週1時間まで）。**

---

## 1. 書き方の原則：出典の文字をそのまま使う

イベントの項目（タイトル・日付・時刻・会場・主催・料金）は、出典に書かれている文字をそのまま使います。
AIが言葉を作ると、それがサイトとSNSに広がります（2026-11-14 のオール早慶戦の誤タイトルがこの例）。

| してよいこと | してはいけないこと |
|---|---|
| 出典の表記をそのまま写す | **翻訳**（英語→日本語、日本語→英語）。英語の題名は英語のまま、日本語は日本語のまま |
| 全角・半角、空白の整え | **略記の展開・補足**（例：日程表の「vs全慶應」を「全慶應義塾大学」と書く） |
| `naming-dictionary.json` にある正式表記への統一 | **記憶による訂正**（例：「小野記念講堂」を「小野梓記念講堂」に直す。正式名称は前者） |
| 試合を「<部の名前> vs<相手>」「<大会名>(<部の名前>)」の形で書く（相手・大会名は出典の表記のまま） | 出典にない情報で項目を埋める（推測の料金・時刻・会場） |
| 同じ企画の複数日を「(1日目)」「(2日目)」で分ける | 複数の出典の言葉を組み合わせて新しい題名を作る |

- **英語版ページしか見つからないとき**：日本語の元ページがないか探し、あればそちらを出典にする。大学のサイトは URL に `news-en` を含んでも日本語のことがある（どらま館など）ので、中身で判断する。
- **公式の日英表記が両方あるとき**だけ、辞書の別名として両方を持つ（3章）。
- **主催が複数のとき**は全員を「・」でつないで書く（例：`早稲田大学野球部・慶應義塾体育会野球部`）。共催・協力・後援は主催に入れない。
- **description**（紹介文）は事実を自分の言葉で1〜2文。出典の文章は写さない（`LEGAL_GUARDRAILS.md`）。

## 2. 公開の判定：A / B / C

新しく追加・変更したイベントは、`node scripts/verify-event-sources.js --changed-from origin/main --apply` で
出典の文字列と機械的に照合し、次の3つに分けます。判定はプログラムが行い、AIの判断で上書きしません。

| 区分 | 条件 | 扱い |
|---|---|---|
| **A 自動公開** | タイトル・日付・開始時刻・会場・主催・料金（書いたもの）がすべて、出典のそのイベントの記載にある | そのまま公開 |
| **B 一部保留** | タイトル・日付・主催は確認できたが、開始時刻か会場がデータにない（欠けているだけで、食い違いはない） | **試験期間（2026-11-28まで）は非公開**（`reviewStatus:"partial"`）。件数と誤りを数えてから公開の可否を決める。SNSには使わない |
| **C 確認待ち** | 出典にない文字列がある／出典と食い違う／出典を読めない／中止・延期の告知がある | 非公開（`reviewStatus:"pending"`）で運営者の確認待ち。1日10件まで提示 |

- **文字列が出典にあるだけでは不十分**なので、照合は「そのイベントの記載の近く」に絞り、開場と開始の違い、中止・延期の告知も見る。
- **Instagram や JS で描画されるサイト**は直接読めないため、読んだ担当が「日付・時刻・会場・題名の短い引用」を根拠として渡す（`.verify-evidence/`、コミットしない）。根拠がなければ C。
- **既存イベントの変更が C** のときは、その変更を取り消して確認待ちに回す（公開中の情報を確かめずに書き換えない）。
- **辞書にない会場・団体**でも、主催者か大学の公式情報で確認できれば、出典の表記のまま掲載してよい（団体IDは空のまま）。団体IDを推測で付けない。

## 3. 正式名称の辞書（`scripts/naming-dictionary.json`）

- 会場：正式名称・表示名・別名・根拠URL。**別名と完全に一致するものだけ**を表示名にそろえる（教室名などを消さないため）。誤記は `forbidden` に入れて検査で止める。
- 団体：`organizations.js` の `name` は大学の公認団体一覧の表記で、団体自身の名乗りと違うことがある（例：「交響楽団」と「早稲田大学交響楽団」）。表示名は辞書の `organizers` に持つ。
- **辞書に追加・変更できるのは運営者だけ。** AIは候補を出すだけ（`node scripts/check-event-data.js --candidates`）。運営者は週1回まとめて承認する（4章）。

## 4. 運営者の作業（上限：1日10件・週1時間）

| いつ | 何を | 量 |
|---|---|---|
| 毎日 | Google ドライブの `要確認_YYYYMMDD.txt` の行頭に OK / NG を書く | 10件まで（超えた分は翌日へ） |
| 毎日 | Chrome に準備された SNS 投稿画面を確かめてボタンを押す | 上限 X 6本・Instagram 3本 |
| 週1回 | `週次確認_YYYYMMDD.txt`：公式サイトの取りこぼし候補（20分）・辞書の承認（15分）・新しい Instagram アカウント候補（10分）・誤りの振り返り（15分） | 合計1時間 |

確認の対象を増やすときは、別の確認を減らす。

## 5. 料金の書き方

`feeType` は料金の性質、`feeText` は表示する文字です。

| 状態 | feeType | feeText |
|---|---|---|
| 公式に無料と書いてある | `free` | 「無料」「入場無料」など出典の表記 |
| 公式に金額が書いてある | `paid` | 金額と条件を出典どおり（例：`S席5,000円／A席4,000円`） |
| 有料だが金額が書いていない | `paid` | 「有料（金額未掲載）」 |
| 公式に「未定・後日発表」とある | `unknown` | **料金未公表** |
| 調べていない・見つからない | `unknown` | **料金未確認** |

「書いていないから無料だろう」は推測です（検査でエラーになります）。

## 6. SNS（X・Instagram）

- 投稿の候補は**公開済みの A 区分のイベントだけ**。B・C・確認待ちは使わない。
- 投稿画面を作る前に、出典ページを開いて日時・会場・タイトルを照合する。食い違いがあれば投稿せず、`修正依頼_YYYYMMDD.txt` に書いて翌朝の作業で直す。
- 本数は目標ではなく**上限**（1日 X 6本・Instagram 3本）。条件を満たす候補が少ない日は少なくてよい。
- 投稿準備は、その日の公開処理が終わってから（`https://wasedacalendar.com/scripts/daily-cycle-status.json` の `date` が今日）。

## 7. 情報源

- 掲載数の伸びしろは大学の公式サイト側にある（2026-11-14 時点、今後30日の出典は大学公式45件・Instagram 19件）。週次の取りこぼし監査で、大学のイベント一覧・学部の告知・早稲田祭の企画一覧と照らし合わせる。
- Instagram の巡回は件数を増やさない（1回45件まで）。画像の読み取りも追加しない。
- 主催者・閲覧者からの修正依頼と情報提供は、各イベントページの「情報の誤りを報告する」とお問い合わせフォームで受け付ける。届いた依頼も出典で確かめてから反映する。
- 新しい Instagram アカウントは、名前が似ているだけでは巡回対象に入れない。大学の公認団体一覧・団体の公式サイト・既知の公式アカウントからの案内など、根拠のあるものを週次の確認で運営者が承認する。1つの団体に複数のアカウント（新歓用など）があってよい。

## 8. 品質の指標（週次の振り返りで見る）

新規掲載数・A/B/C の件数・要確認の処理件数と持ち越し・誤り報告の件数・取りこぼし監査で見つかった未掲載・SNSからのアクセス。
誤りの「欠け（料金未確認など）」と「間違い（誤った日時・会場）」は分けて数える。
