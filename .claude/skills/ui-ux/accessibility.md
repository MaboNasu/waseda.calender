# アクセシビリティ

WCAGの考え方に基づく、実務で使えるチェック項目。**アクセシビリティは「後でやる品質改善」ではなく、UI設計の基本条件として扱う。** 新しいUIを設計する時点から組み込み、後付けしない。

## Text contrast（テキストコントラスト）

- 本文テキストはコントラスト比 4.5:1 以上（WCAG AA、通常サイズ）を目安にする。
- **現状の主要な色の組み合わせ確認**: `--enjy (#8B0000)` on `--white`、`--text-primary (#1F2937)` on `--gray-50`は十分なコントラストがある。新しい薄い色（`--enjy-pale`等）にテキストを重ねる場合は、背景に対して十分暗い文字色を選ぶ（カテゴリタグは既にこの配慮がされた配色になっている——`design-system.md`のColors参照）。

## Non-text contrast（非テキストのコントラスト）

- ボタンの境界線、フォーカスリング、アイコンなど、テキスト以外でも意味を持つ要素は3:1以上を目安にする。
- `.btn-ghost`のボーダー（`--enjy`）は背景（白）に対して十分なコントラストがある。

## Font size

- 極端に小さい文字（0.68rem前後のタグ・チップ）は、情報の重要度が低い補助的なラベルに限定する。参加判断に必須の情報（日時・場所・料金）を極小フォントだけに頼らせない。

## Focus state（フォーカス状態）

- キーボード操作でフォーカスが当たっている要素が視覚的に分かること。
- モーダルは`setupModal`でTabキーによるフォーカストラップが実装済み——新しいモーダルもこのパターンを踏襲する。
- 新しいインタラクティブ要素（ボタン・リンク・カスタムUI）にフォーカス時のスタイルが消えていないか確認する（`outline: none`だけで潰していないか）。

## Keyboard navigation（キーボード操作）

- クリックだけでなくキーボードだけでも同じ操作が完結できること。
- `<button>`/`<a>`を使っていれば基本的にキーボード操作は担保される。`<div onclick>`のような非セマンティックな要素にクリックハンドラだけを付ける実装は避ける。
- モーダルのEscキーでの閉じる操作は既存パターン（`setupModal`）で実装済み——新しいモーダル/ドロワーでも同様にする。

## Semantic HTML（セマンティックHTML）

- ボタンは`<button>`、リンクは`<a href>`、見出しは`<h1>`〜`<h3>`を使う。`<span onclick>`のような疑似ボタンを作らない。
- 折りたたみトグルの実装例（`section-title-toggle`）は`<button aria-expanded="...">`で、APG（ARIA Authoring Practices）のアコーディオンパターンに沿っている——新しい開閉UIもこの形を踏襲する。

## Heading structure（見出し構造）

- ページ内で見出しレベルを飛ばさない（h1の次にいきなりh3、等をしない）。
- 団体個別ページ（`org.html`/`org/{id}.html`）では団体名をh1、一覧ページのサイドペインでは同じ内容をh2として出し分けている（`renderOrganizationDetail`の`headingTag`オプション）——1ページに複数のh1を作らないための工夫として維持する。

## Link text（リンクテキスト）

- 「こちら」「詳細を見る」だけの曖昧なリンクテキストを避け、遷移先が予測できる文言にする（Information Scent、`principles.md`参照）。
- 現状「公式サイトを見る」「参加申し込みはこちら」等、具体的な文言になっている——この水準を維持する。

## Button semantics（ボタンのセマンティクス）

- ページ遷移を伴わない操作は`<button type="button">`、ページ遷移を伴うものは`<a href>`を使う（現状のコードはこの区別を概ね守っている）。

## ARIA-label

- アイコンのみのボタン（テキストラベルがないもの）には`aria-label`を付ける。
- 装飾目的のアイコン（例: 折りたたみシェブロン）は`aria-hidden="true"`にし、開閉状態そのものは親要素の`aria-expanded`で伝える（現状の`.section-toggle-icon`/`.filter-toggle-icon`の実装パターン）。

## Form labels（フォームラベル）

- 全ての入力要素に`<label for="id">`を紐づける。プレースホルダーだけをラベル代わりにしない。
- 現状のフィルターセレクト（`filter-category`等）は`<label for>`で紐づけ済み——新しいフォーム要素もこれを踏襲する。

## Error messages（エラーメッセージ）

- 何が起きたか・どうすれば直るかが分かる文言にする。
- 現状`contact.js`等のエラー表示は改善余地がある可能性があるため、フォーム関連のUI相談を受けた際は個別に確認する。

## Color-only information（色のみによる情報伝達）

- 色だけで意味を伝えない（色覚特性によって判別できないユーザーがいる）。
- 参加費タグ（緑=無料/赤=有料）は色に加えて必ずテキスト（金額・「無料」等）が併記されている——この原則を崩さない。カテゴリタグも同様に、色だけでなくカテゴリ名のテキストを常に表示する。

## Reduced motion（動きの低減）

- **既にグローバル対応済み**: `style.css`の`@media (prefers-reduced-motion: reduce)`で全アニメーション・トランジションが`0.01ms`に短縮される。新しいアニメーションを追加する場合も、この既存のグローバルルールでカバーされるため、個別に`prefers-reduced-motion`対応を書く必要は基本的にない（既存のCSSトランジション・アニメーション機構を使う限り）。JavaScriptで独自にアニメーションを実装する場合は、この設定を尊重するかどうか個別に確認する。

## Touch targets（タップ領域）

`mobile-guidelines.md`のTouch Target項目と同じ基準（44px前後）を、アクセシビリティの観点からも満たす（運動機能に制約があるユーザーにとっても重要）。
