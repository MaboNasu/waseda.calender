# お問い合わせフォーム（Google Apps Script）セットアップ手順

`contact.html` のお問い合わせフォームを実際に動かすには、Googleスプレッドシート側の準備が必要です。

> すでに以前のバージョンをデプロイ済みの方は、「団体マスタ」シートの追加と、既存シートへの列追加、コードの再デプロイが必要です。該当する手順には📌マークを付けています。

> 📌 「Googleカレンダーから予定を取り込む」機能を追加しました。この機能はスプレッドシートに書き込みを行わない読み取り専用の入力補助（`fetchGCalEvents`）のため、シートの列追加は不要です。手順6（再デプロイ）だけ行えば反映されます。

> 📌 メール送信数を抑えるための変更を行いました。シートの列追加は不要で、再デプロイのみで反映されます。
> - **管理者通知メールは、優先度「高」（修正・削除依頼、広告協賛の相談）の時だけ届きます。** 通常の掲載依頼では管理者通知メールは送られなくなったので、スプレッドシートの「お問い合わせ」シートを定期的に確認してください（申請者への確認メールは今まで通り全件届きます）。
> - 同一メールアドレスからの連続送信の制限（20秒間隔・1時間30件まで）に加え、**1日あたりの受付件数そのものにも上限（45件/日）**を設けました。上限に達すると、それ以降の送信は「本日は多くのお問い合わせをいただいたため、受付を終了しました」というメッセージで丁重にお断りされます（翌日0時＝日本時間で自動的にリセットされます）。

---

## 1. Googleスプレッドシートを準備する

### 既存の「お問い合わせ」シート（すでにある場合はそのまま）

1行目の見出し（A列から）は変更不要です。**既存データの列の意味が変わらないように、新しい列はすべて末尾に追加します。**

既存の見出し（変更なし）:
```
受付番号 | 送信日時 | お問い合わせ種別 | 初回自己申告 | 自動判定 | 過去問い合わせ回数 | お名前 | メールアドレス | 団体名・所属 | 団体URL・SNS | 対象イベント名 | 対象ページURL | 希望掲載日 | 申込URL・詳細URL | 予算感 | お問い合わせ内容 | 対応状況 | 優先度 | 担当者 | 対応メモ | 最終更新日
```

📌 末尾（V列以降）に、以下の見出しを追加してください:
```
団体ID | 開催日 | 開始時間 | 終了時間 | 場所 | 参考画像・資料URL | 終了日 | 定期開催日一覧
```

`終了日`は複数日にわたるイベント（学事日程の授業週など）の最終日です。単日イベントの場合は空欄になります。
`定期開催日一覧`は、申請者が「定期開催」にチェックを入れて複数の開催日を追加した場合に、すべての開催日をカンマ区切り（例: `2026-07-01,2026-07-08,2026-07-15`）でまとめたものです。`events.js`へ転記する際は、この列の日付ごとに複数イベントを作成する元データとして使ってください。

📌 さらに、**一番左（A列）に新しい列を1つ挿入**してください（A列を右クリック →「左に1列を挿入」）。見出しは`掲載OK`とし、その列全体にチェックボックスを設定します（A列を選択 →「挿入」メニュー →「チェックボックス」、または「データ」→「データの入力規則」→ 条件「チェックボックス」）。

この列は、送信内容（メールの内容・申込内容）を人が確認し、`events.js`に反映してよいと判断したものだけにチェックを入れる運用を想定しています。**`events.js`へ反映する際は、チェックが付いている行だけを対象にしてください。**

まだスプレッドシートを作っていない場合は、[Googleスプレッドシート](https://sheets.google.com/)で新規作成し、シート名（タブ）を`お問い合わせ`にして、`掲載OK`列＋既存見出し＋末尾の追加見出し（全29列）を1行目に入力してください。

### 📌 「団体マスタ」シートを新規追加する

同じスプレッドシート内に、新しいシート（タブ）を追加し、シート名を`団体マスタ`にしてください。1行目に以下の見出しを入力します。

```
団体ID | 登録日時 | 団体名 | 担当者名 | メールアドレス | 団体SNS・WebサイトURL | 団体紹介文 | 認証トークン | 過去掲載回数 | 最終掲載依頼日 | 管理メモ
```

### スプレッドシートIDの確認

ブラウザのアドレスバーに表示されているURLから、スプレッドシートIDをコピーしておきます。

```
https://docs.google.com/spreadsheets/d/【ここがスプレッドシートID】/edit
```

## 2. Apps Scriptを開く

1. スプレッドシートのメニューから「拡張機能」→「Apps Script」を選択する
2. エディタが新しいタブで開く

## 3. 📌 `gas/contactForm.gs` のコードを貼り付ける（更新）

1. エディタ内の既存コードを全て削除する
2. このリポジトリの [gas/contactForm.gs](../gas/contactForm.gs) の内容を全てコピーし、貼り付ける
3. 上部の保存アイコン（💾）またはCtrl+Sで保存する

以前のバージョンから、定数名が変わっています（`SHEET_NAME` → `INQUIRY_SHEET_NAME`）。次の手順で必ず設定し直してください。

## 4. スプレッドシートID・シート名を設定する

貼り付けたコードの上部にある以下の行を書き換える。

```javascript
const SPREADSHEET_ID = 'ここにスプレッドシートIDを入れる';
const INQUIRY_SHEET_NAME = 'お問い合わせ';   // シート名を変えていなければそのままでOK
const ORG_SHEET_NAME = '団体マスタ';         // シート名を変えていなければそのままでOK
```

## 5. 管理者メールアドレスを設定する

同じく上部にある以下の行を、通知を受け取りたいメールアドレスに書き換える。

```javascript
const ADMIN_EMAIL = 'ここに管理者メールアドレスを入れる';
```

## 6. 📌 Webアプリとして再デプロイする

コードを更新した場合、上書き保存だけでは反映されません。

1. エディタ右上の「デプロイ」→「デプロイを管理」
2. 既存デプロイの編集（鉛筆アイコン）をクリック
3. バージョンを「新バージョン」にして「デプロイ」
4. 権限確認画面が出た場合は、内容を確認して「許可」する

> 初めてデプロイする場合は「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」を選び、実行ユーザー「自分」、アクセスできるユーザー「全員」に設定してください（「全員」にしないと、Googleにログインしていないサイト訪問者からの送信が拒否されます）。

> 📌 今回から画像アップロード機能（Google Drive保存）が追加されたため、権限確認画面に「Googleドライブ内のファイルの表示、編集、作成、削除」という項目が新たに表示されます。内容を確認して「許可」してください。

新バージョンをデプロイしても、WebアプリのURL自体は変わりません。URLが変わっていなければ、[contact.js](../contact.js)側の設定変更は不要です。

## 7. WebアプリURLをフロントエンド側に設定する（初回のみ）

[contact.js](../contact.js) の先頭にある以下の行を、デプロイ済みのURLに書き換える。

```javascript
const CONTACT_GAS_URL = 'https://script.google.com/macros/s/YOUR_DEPLOYMENT_ID/exec';
```

## 8. テスト送信の確認方法

### 新規団体としての送信
1. `contact.html` を開き、「初めて掲載依頼をする」を選んでイベント情報を入力し送信する
2. 「お問い合わせを受け付けました」というメッセージと受付番号が表示されることを確認する
3. 「お問い合わせ」シートに1行、「団体マスタ」シートに1行、それぞれ追加されていることを確認する
4. 確認メールに、次回用の専用URL（`?orgId=...&token=...`）が記載されていることを確認する

### 登録済み団体としての送信
1. 上記の確認メールに記載されたURLを開く
2. 団体名・担当者名・メールアドレス等が自動入力され、「登録済み団体として入力中です」と表示されることを確認する
3. イベント情報だけ入力して送信し、「団体マスタ」シートの該当行の「過去掲載回数」が増えていることを確認する
4. URLの`token`を適当な文字列に変えてアクセスし、認証エラーになって新規入力にフォールバックすることを確認する

### 画像アップロード（登録済み団体のみ）
1. 登録済み団体として認証された状態で、「イベント画像・資料を添付」欄から画像を選んで送信する
2. Googleドライブに「Waseda Calendar 添付画像」フォルダが自動作成され、画像が保存されていることを確認する
3. 「お問い合わせ」シートの「参考画像・資料URL」列に、Driveの共有リンクが自動で入っていることを確認する

### 📌 Googleカレンダーからの予定取り込み
1. 自分のGoogleカレンダーで、テスト用の予定を1件以上作成する（今日以降の日付）
2. カレンダーの「設定と共有」→ 対象カレンダーの「カレンダーの統合」から、「限定公開URL（iCal形式）」をコピーする（自分しか見られない予定でも取得できる）
3. `contact.html`で「初めて掲載依頼をする」を選び、「イベント詳細」欄上部の「Googleカレンダーから予定を取り込む」にそのURLを貼り付けて「予定を取得」を押す
4. プルダウンに直近の予定が表示され、選択するとイベント名・開催日・場所などが自動入力されることを確認する

## 9. よくあるエラーと対処法

| 症状 | 原因・対処法 |
|---|---|
| 送信しても何も起こらない／コンソールにCORSエラーが出る | デプロイ設定の「アクセスできるユーザー」が「全員」になっていない可能性 |
| 「送信に失敗しました」と表示される | `CONTACT_GAS_URL` が正しいURLになっているか確認。コード修正後に再デプロイ（新バージョン）し忘れていないか確認 |
| スプレッドシートに行が追加されない | `SPREADSHEET_ID` ・ `INQUIRY_SHEET_NAME` ・ `ORG_SHEET_NAME` が正しいか確認。シート名の前後に余分なスペースが入っていないか確認 |
| 団体情報が自動入力されない | URLの`orgId`と`token`が「団体マスタ」シートの値と完全に一致しているか確認。コピー時に余分な空白や改行が入っていないか確認 |
| メールが届かない | 迷惑メールフォルダを確認。Apps Scriptの実行ログ（エディタ左の時計アイコン「実行数」）でエラーが出ていないか確認。個人のGoogleアカウントは1日に送信できるメール数に上限があるため、テストを何度も繰り返すと上限に達することがある |
| 「このアプリは確認されていません」という警告が出る | 自分が作成したスクリプトなので問題ない。「詳細」→「（プロジェクト名）に移動」→「許可」と進めば使用できる |
| 受付番号・団体IDが重複する | `LockService` が正しく動いているか確認。通常は自動で排他制御されるため発生しない想定 |
| 画像を送ってもURLが入らない | 再デプロイ時にGoogleドライブへの権限を「許可」したか確認。画像が5MBを超えていないか、image/*形式かどうかも確認 |
| 「Googleカレンダーから予定を取り込む」でエラーになる | URLが`https://calendar.google.com/calendar/ical/`で始まるiCal形式URLか確認（カレンダーの「統合」欄からコピーしたものに限る）。今日以降の予定がカレンダーに無いと「今後の予定が見つかりませんでした」と表示される |
| 通常の掲載依頼で管理者通知メールが来ない | 仕様です。優先度「高」（修正・削除・広告協賛）以外は管理者通知を送らない設定にしています。スプレッドシートを確認してください |
| 「本日は多くのお問い合わせをいただいたため」と表示されて送信できない | 1日の受付件数の上限（45件）に達しています。日本時間の0時に自動でリセットされます。頻発する場合は`DAILY_SUBMISSION_LIMIT`の値を見直してください |
